# 교실데스크 0.3.0 검수 범위

## 현재 실행 결과

- Node 검사: **122개 통과, 실패 0개, 보류 0개**. 실제 0.3.0 설치 파일을 만든 뒤 `CLASSDESK_REQUIRE_BUILD=1 CLASSDESK_REQUIRE_INSTALLER=1` 엄격 모드로 실행했다.
- 실제 Chromium 검사: **기존·통합 36개와 개선 회귀 8개, 운동장 전용 6개, 합계 50개 통과**. 페이지 오류와 리소스 로드 실패 없음.
- Windows 호스트: 실제 **x64 .NET Framework 4.8 GUI EXE**, 버전 0.3.0을 교차 컴파일. 경고 0개·오류 0개. PE32+·CLR·제품 리소스·WebView2 의존성을 확인했다.
- 실제 NSIS 설치 파일·포터블·대응 소스를 생성하고 압축 추출·해시·소스 재빌드까지 확인했다. Windows 설치 마법사 실행 검수와는 구분한다.

## 0.3.0 운동장: 학생 군중과 둥근 빈자리

- 머리·머리카락·옷·팔·다리·신발·그림자를 가진 작은 학생 **7,680명**을 고정 설계 좌표에서 화면 크기에 투영한다. 아이콘을 옮겨도 다른 학생을 무작위로 다시 배치하지 않는다.
- 사각형 그룹 윤곽을 둥근 곡선으로 바꾸되 실제 아이콘 그림의 모서리를 빈자리 안에 남긴다. 전환용으로 정점 수가 바뀌어도 먼저 일직선 중간점을 제거해 둥글기가 갑자기 달라지지 않게 한다.
- 빈자리와 몸이 겹치는 학생은 중심이 밖에 있어도 몸 전체를 숨긴다. 실제 곡선과 학생 그림 범위를 비교하므로 둥근 모서리 바깥을 사각형으로 함께 지우지 않는다.
- 깨끗한 바닥과 학생이 그려진 바닥을 별도 그림으로 보관하되 총 픽셀 예산은 유지한다. 필요한 작은 영역만 복사하고, 학생 위치를 공간 격자로 찾아 작은 구역마다 모든 학생을 전수 탐색하지 않는다.
- Chromium에서 빈자리 내부의 학생 소멸, 둥근 모서리 바깥의 학생 유지, 이동 후 원래 자리의 픽셀 복원, 다른 그룹·군중의 전환 중 픽셀 고정을 확인했다.
- 100%·200% 배율에서 여백 8·22·64, 구불거림 0·1, 선·채움·둘 다를 조합해 아이콘 영역이 비는 것을 확인했다. 이름·ID·색 모델과 네이티브 편집 영역은 바꾸지 않았다.
- 설정 미리보기와 **실제로 내려받은 PNG**를 디코딩해 학생 그림과 비워진 아이콘 자리를 확인했다. PNG에 파일 아이콘을 중복해서 그리지 않는다.
- 소프트웨어 Chromium의 4K·500개 독립 그룹 측정에서 준비 후 중앙 렌더 시간 약 **64.5ms**를 기록했다. 초기 그림 생성은 별도이며 Windows GPU 성능을 의미하지 않는다.

## 기존 개선 사항별 확인

1. **아이콘 그림 중심 계산**
   - Explorer의 `LVM_GETITEMRECT`에 `LVIR_ICON`을 지정하며 파일명·전체 선택 사각형을 그룹 계산에 사용하지 않는다.
   - 실패·잘못된 사각형이 섞인 읽기를 정상적인 삭제로 처리하지 않는다.
   - 실제 운영 C# 식별자 추적·유효성 검사 코드를 Linux에서 실행했다. 삽입·삭제·재정렬·이동·크기 변경·숨김/표시에서 불투명 ID를 확인했다.
   - Windows에서 선택할 때의 실제 글자 영역 변화는 실기기 확인 범위로 남는다.
2. **변경된 구역만 전환**
   - 지속 ID로 이전·다음 장면을 연결하며 변경 없는 그룹의 좌표·색·윤곽은 고정한다.
   - 경계 전체를 0부터 드러내지 않고 약 0.28초 동안 변경된 윤곽을 보간한다. 다른 정점 수·방향·시작 위치와 전환 중 재변경을 검사했다.
   - Chromium에서 애니메이션 시계를 제어하며 설정 미리보기와 실제 배경 진입점 모두 **첫 프레임·중간·끝 프레임의 변경 없는 구역 픽셀 해시가 동일**한 것을 확인했다.
   - 중간 프레임에서 움직인 구역이 이전·최종 위치 사이를 지나며 모션 끄기·정지에서는 최종 장면을 바로 표시한다.
3. **바탕화면 직접 이름 편집**
   - 이름표와 동일한 글꼴·측정 정보를 바탕으로 물리 좌표의 이름표·연필 영역을 전달한다.
   - 호스트는 24×24 편집 버튼 영역만 입력을 받는 바탕화면 자식 창을 사용한다. 다른 프로그램 위에 전체 화면 입력 창을 올리는 방식이 아니다.
   - DPI 문맥·바탕화면 부모·아이콘 겹침을 확인할 수 없으면 버튼을 숨기는 쪽으로 처리한다. 명시적인 `[0,0,0,0]`은 임의 위치로 옮기지 않는다.
   - 작은 이름 편집창은 Enter 저장·Escape/바깥 클릭 취소·한글 입력기 조합 처리를 포함한다.
   - 실제 C#의 영역 검사·카탈로그 검증·이름 한 건 병합·40글자 일반 텍스트 제한·중복 저장 억제를 실행했다.
   - 브라우저에서 실제 `groupState` 발신, 안전한 좌표, 중복 억제, 설정 창의 이름·카탈로그 수신과 역방향 저장 반복이 없는 것을 확인했다.
   - 왼쪽 위 첫 아이콘이 y=10·40인 일반 세로 배치에서도 이름·연필을 함께 빈 자리로 옮기고, Windows 파일명 셀을 침범하지 않는 실제 편집 영역이 나오는 것을 확인했다.
   - **Windows에서 마우스로 연필을 누르고 한글을 입력하는 실제 동작은 미검수**다.
4. **구역 ID·이름·색 보존**
   - 구성원 해시와 지속 ID를 분리하고 테마별 `groupCatalog`를 저장한다. 0.1의 해시 이름을 이관한다.
   - 0.1의 `native-N` 식별자가 0.2에서 불투명 ID로 바뀌는 실제 초기 메시지로 업그레이드를 재현했다. 같은 구성의 저장 이름·ID·색을 설정 창·칠판·해변·초원에서 유지한다. 첫 카탈로그에서만 이관하며 기존 카탈로그를 덮어쓰지 않는다.
   - 추가·삭제·재정렬·전체 이동·합치기/나누기·복원·충돌·500그룹에서 결정성·입력 불변성과 이름·색 보존을 검사했다.
   - 같은 장면을 다시 처리해도 카탈로그 JSON이 바뀌지 않는다. 숨긴 아이콘 메시지로 기록을 비우지 않는다.
   - 구역끼리 위치를 교환하거나 이동·구성 변경이 함께 일어나도 신뢰 가능한 불투명 구성원 ID를 먼저 비교한다. 동일 비율의 분할·병합은 공간 정보를 보조 기준으로 결정한다.
   - 17,000개 누적 구성원을 가진 실제 생성 가능한 기록과 512×500 구성원 최대 용량을 C#에서 검사했다. JSON 수신·직렬화 용량도 같은 유한 한도로 맞췄다.
   - 이름 사전은 최대 512개이며 현재 ID를 우선한다. 101개·500개 이름과 오래된 기록 포화 상태에서 다른 이름을 수정해도 현재 이름이 사라지지 않는다.
   - 표현 초기화는 이름·카탈로그를 보존한다.
5. **테두리 구불거림**
   - `waviness` 0~1의 범위·기본값 0.25·테마별 저장/복원을 검사했다.
   - 0과 1에서 실제 그려지는 윤곽이 다르고 같은 값에서는 매 프레임 무작위 흔들림을 만들지 않는 것을 확인했다.
6. **선·색칠 표현**
   - `outline`·`fill`·`both`를 검증하며 학교 4종에 실제 반투명 채움과 경계 표시를 적용한다.
   - Canvas 그리기 명령과 Chromium 실제 픽셀의 차이, UI 선택과 재시작 후 복원을 확인했다.
7. **트레이·Alt+Tab**
   - 배경 창은 첫 표시·핸들 재생성 전부터 `WS_EX_TOOLWINDOW`·`WS_EX_NOACTIVATE`를 적용하고 `WS_EX_APPWINDOW`를 제거한다.
   - 직접 연 설정 창은 일반 작업 창으로 두며 최소화하면 `Hide()`로 트레이에 숨긴다. 트레이에서 다시 열 때 복원 경로를 유지한다.
   - Microsoft의 공식 확장 창 스타일 문서와 회귀 계약 검사·실제 EXE 컴파일을 확인했다.
   - **Windows의 실제 Alt+Tab 목록을 열어 확인하지는 않았다.**

## 기존 기능 회귀

- 원본 해변·초원 WebGL2 장면을 그대로 재사용하며 학교 4종을 더한 6종을 확인했다.
- 원본 풍경을 정지한 상태에서 이름·카탈로그 등 덧그리기 설정만 바꿔도 비싼 원본 셰이더를 다시 그리지 않는다.
- 100%·125%·200% 배율에서 6종 모두 물리 좌표 그룹·ID·이름과 화면 비율을 비교했다. 70px 간격을 56px에서 분리하고 80px에서 병합했다.
- 예시 아이콘 드래그·방향키·삭제·되돌리기, 6종별 이름 저장·전환, 실제 PNG 다운로드, 안내창, 390px·320px 반응형과 저장소 차단을 확인했다.
- 글꼴·테마·이미지는 로컬 파일이다. 실제 파일명·내용을 읽거나 이동·업로드하지 않는다.

## 재현 명령·보고서

```sh
CLASSDESK_REQUIRE_BUILD=1 npm test
npm run test:browser
node tests/browser-improvements.mjs
node tests/browser-playground.mjs
# 실제 설치 파일 생성 후
CLASSDESK_REQUIRE_BUILD=1 CLASSDESK_REQUIRE_INSTALLER=1 npm test
```

- Node 원본 출력: `artifacts/qa/node-tests.tap`
- 기존·통합 브라우저: `artifacts/qa/summary.json`
- 개선 회귀 브라우저: `artifacts/qa/improvements.json`
- 운동장 전용 브라우저·대량 렌더 측정: `artifacts/qa/playground.json`
- 검수 직후 소스 해시: `artifacts/qa/review-tree-manifest.json`

Linux ARM64에서 소프트웨어 WebGL로 전체 검수를 수행하므로 수 분이 걸릴 수 있다. 짧은 시간 제한으로 중단된 실행을 검수 완료나 제품 오류로 해석하지 않는다. 일부 항목만 실행한 보고서를 전체 검수 결과로 사용하지 않는다.

## 릴리스 산출물 검증

- 실제 `ClassDesk-0.3.0-win-x64-Setup.exe`를 NSIS로 컴파일했다. 현재 사용자 설치·시작 메뉴·제거 항목과 Microsoft WebView2 설치 도구를 포함한다.
- 엄격 모드 검사는 실제 설치 EXE를 7-Zip으로 다시 추출하고 모든 포함 파일을 현재 파일·설치 manifest의 SHA256과 비교했다. 이름만 같은 이전 EXE나 빠진 학생 그림 모듈을 통과시키지 않는다.
- 별도 소스 ZIP의 모든 파일과 현재 작업 트리의 바이트를 비교했다. 실제 ZIP을 새 폴더에 풀어 호스트를 재빌드했고 배포 `ClassDesk.exe`와 **바이트 단위로 일치**했다.
- 설치형에도 같은 GPL 소스 ZIP을 동봉하며 포터블 ZIP도 제공한다. 원본 저작권·라이선스, 자체 아이콘, WebView2·로컬 글꼴 라이선스를 보존한다.
- Microsoft 서명 검증은 공식 WebView2 설치 도구의 기본 서명·게시자·인증서 체인에 대한 것이다. 교실데스크 자체와 Setup.exe는 미서명 테스트 배포본이다.
- 설치 마법사·실제 Windows 실행을 Linux의 컴파일·압축 추출 검사와 구분한다.

## Windows 실기기 확인 순서

1. 원래 배경과 아이콘 배치를 기록한다. 승인된 테스트 PC에서 `ClassDesk-0.3.0-win-x64-Setup.exe`를 설치한다.
2. 해변·초원·학교 테마 4종을 선택하고 실제 아이콘 이동·추가·삭제를 확인한다.
3. 여러 줄 이름의 파일을 선택·해제해도 구역이 달라지지 않는지, 일부 이동 때 다른 구역 선이 사라지지 않는지 확인한다.
4. 이름 옆 연필로 한글을 입력한다. Enter 저장·Escape/바깥 클릭 취소와 일반 파일 선택·더블 클릭·이름 변경·다른 프로그램 입력이 정상인지 확인한다.
5. 이름 저장 후 구성 변경·표현 초기화·테마 전환·종료·재실행을 확인한다.
6. 구불거림의 최솟값·최댓값과 선·색칠·둘 다를 확인한다.
7. 설정 창을 닫거나 최소화한 뒤 Alt+Tab에서 배경 창이 빠지는지 확인한다. 트레이로 설정을 다시 열면 일반 창으로 보이고 최소화하면 숨는지 확인한다.
8. Explorer 재시작·실제 DPI/해상도 변경·자동 시작·최대화/전체 화면 정지를 확인한다.
9. 종료 시 원래 배경이 복구되고 제거 시 해당 설치의 파일·시작 항목만 정리되며 사용자 설정은 보존되는지 확인한다.

Windows 기본 C# 컴파일러·PowerShell 빌드 경로, 설치 마법사 진행·실제 WebView2 설치·기관 정책·네이티브 입력·Alt+Tab·제거는 실기기 미검수다. 교실데스크와 설치 파일은 미서명 테스트 배포본이며 Microsoft 서명 검증은 포함된 공식 WebView2 설치 도구에만 해당한다. 학교 보안 정책이나 SmartScreen을 임의로 해제하지 않는다.
